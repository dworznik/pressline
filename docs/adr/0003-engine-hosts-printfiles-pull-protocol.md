# Pressline pulls from the Engine over HTTP and the Engine hosts printfile bytes

Printful fetches printfiles by URL and may re-fetch them at confirmation and on later reprints, so someone must host each Printfile durably and immutably. We decided the Engine does: DesignSource is a pull protocol in which Pressline calls the Engine with a Printfile Spec and receives back a Printfile URL plus metadata (hash, dimensions); Pressline validates by reading header bytes from that URL and passes the same URL to Printful. Pressline stores no file bytes, which reduces its storage needs to a database only. In code, `DesignSource` is a TypeScript interface whose shipped implementation is the HTTP client, so an Engine can also be run in-process (tests, single-Worker deploys) by injecting another implementation; the HTTP protocol is the versioned contract.

## Considered options

- Pull returning bytes, Pressline stores them (rejected: adds an object store that must work on both R2 and Vercel Blob, plus lifecycle and egress).
- Push from Engine on "design finalized" (rejected: the Engine would have to know the Printfile Spec, which lives in Pressline).

## Consequences

- Printfile URLs must be immutable: content-addressed or versioned, never a mutable `/designs/:id/printfile.png`.
- Printfile URLs must be reachable by Printful without Pressline-issued credentials (public, or signed with an expiry of months).
- An Engine that deletes or rewrites a Printfile breaks reprints; the Engine docs must say so.
- The same rule applies to Previews: Pressline hot-links the Engine's `previewUrl` and never stores preview bytes.
- The protocol is deliberately small: `GET /designs/{id}`, `POST /designs/{id}/printfile`, `GET /health`. There is no "list designs" endpoint (the Customer always arrives with an ID) and no mockup endpoint (mockups, if wanted, are generated by Pressline from the Printfile URL via the fulfillment provider).
- Mockups follow the same rule. v1 shows the Preview over an Operator-supplied product photo per Offer; `GET /designs/{id}` has an optional `mockups: { [offerSlug]: url }` the Engine may fill and Pressline hot-links. Pressline does not call Printful's mockup generator in core, because its URLs expire and Pressline stores no bytes.
